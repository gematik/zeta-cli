# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this module is

`:connector` is a Kotlin library for talking to the gematik Konnektor (the Telematikinfrastruktur SOAP gateway). It bundles two distinct layers in one module:

- **`de.gematik.connector.api.*` — generated.** SOAP DTOs + `*Port` interfaces produced by `wsdl2openapi2kotlin` from `Konnektor-6.0.1-Consumer.json`. Every file under this package starts with `// Code generated by wsdl2openapi; DO NOT EDIT.` — don't hand-edit; the next regen will overwrite. 83 files, one `Schemas.kt` per package plus `Operations.kt` / `Envelopes.kt` / `<Port>.kt` per service.
- **`de.gematik.connector.*` (top of the package, not under `.api`) — hand-written.** The Kotlin port of koap-go's client surface: `Dotkon` config parser, `ConnectorClient`, `ServiceProxy`, `ServiceDiscovery` (service-directory loader), and the OkHttp TLS/auth helper at `de.gematik.connector.engine.okhttp`.

The boundary is the package: `.api.*` = generator output, everything else = client code. Do not put hand-written code under `.api.*`, do not put generated code outside it.

## Regenerating the API

The generator is an external tool (`wsdl2openapi`, kept in a sibling repo). Recipe lives in the root `justfile`:

```
just generate-connector
```

which runs:

```
java -jar ~/Development/gematik/wsdl2openapi/generator-kotlin/app/build/libs/wsdl2openapi2kotlin.jar \
    --file connector/Konnektor-6.0.1-Consumer.json \
    --output connector/src/main/kotlin \
    --naming connector/naming-strategy.json
```

Inputs that *are* checked in and editable:

- `connector/Konnektor-6.0.1-Consumer.json` — the source spec: Konnektor 6.0.1 (`api-telematik` tag `6.0.1`) and the Basis-Consumer services converted together, so the shared DSS / XMLDSig / ETSI / `tel.error` types are emitted once. The consumer part is `Consumer_1.2.1` plus what differs in older releases still in the field (SignatureService 3.1.0 and 3.0.0, CertificateService 3.0.0). Copied verbatim from `wsdl2openapi/konnektor-6.0.1-consumer.json`.
- `connector/naming-strategy.json` — `basePackage` + regex `packageMappings` that flatten the upstream XML namespaces. Current rules: `de.gematik.ws.* → gematik.*`, `oasis.names.tc.x.y → oasis.xy`, `org.* → *`.
- `connector/build.gradle.kts` — `buildlogic.kotlin-library-conventions` + `kotlin("plugin.serialization")`, plus `ktor-client-core` (api), `kotlinx-coroutines-core`, `kotlinx-serialization-json`, `xmlutil-serialization`, and `ktor-client-okhttp` as `compileOnly` so the OkHttp bridge compiles without forcing OkHttp on every consumer.

The generator does not clean its output directory. Regenerate **in place**: the Konnektor classes are hand-code dependencies and must stay put, and a spec that only adds services must come out as new files only — `git status -- connector/src/main/kotlin/de/gematik/connector/api` showing a modified (`M`) file means an existing class changed and needs a look before it is committed. Only wipe `src/main/kotlin/de/gematik/connector/api/` for a deliberate structural change, and **never wipe other packages** under `de.gematik.connector/`, those are hand-written.

## Generated API layout (`de.gematik.connector.api.*`)

Subpackages reflect the upstream XML namespaces after `naming-strategy.json` mapping:

- `etsi022312`, `etsi01903132` — ETSI TS 102 231 / 101 903 v1.3.2 trust-list types.
- `gematik.conn.<service><version>` — Konnektor service ports and DTOs (`eventservice72`, `cardservice81…820`, `signatureservice74/75`, `certificateservice60/601`, `encryptionservice61/611`, `authsignatureservice74/741`, `cardterminal*`, `connectorcommon50`, `connectorcontext20`, …).
- `gematik.consumer.<service><version>` — Basis-Consumer service ports and DTOs, one package per namespace generation: `signatureservice32` / `31` / `30`; CertificateService 3.0.1 (`certificateservice30` port/envelopes, payload types in `certificateservice31`, `certificateservicecommon21`) and 3.0.0 (`certificateservice300`, `certificateservicecommon20`); shared `consumercommon20`, `encryptionservice30`. No `Context`: operations take only a `CardHandle`.
- `gematik.int.version.productinformation11`, `gematik.tel.error20` — gematik internal types.
- `oasis.dss10core`, `oasis.dssx10profiles.{signaturepolicy,verificationreport}` — OASIS DSS.
- `w3200009.xmldsig`, `w3200104.xmlenc` — W3C XML Signature / Encryption.
- `soap` — the one minimal hand-shaped surface generators emit: `SoapEnvelope` marker interface (`isFault(): Boolean`) and `SoapOperation(name, soapAction, bindingType)`. Every generated request/response has a `*Envelope` that implements `SoapEnvelope`.

Service port interfaces (`<Service>Port`) are plain interfaces, **not suspend**, with no Ktor/HTTP wiring. They exist for type completeness; the actual transport is `de.gematik.connector.ServiceProxy` (see below).

## Hand-written client (`de.gematik.connector.*`)

Layered on top of the generated `.api.*` types. Patterns are kept Kotlin/Native-friendly: stdlib `Base64`, no `java.io.File`, no JVM-only crypto types in pure data classes — JVM-only code (TLS / PKCS#12) is confined to `DotkonSecurity.kt` and `engine/okhttp/`.

- **`Dotkon.kt`** — `Dotkon` data class + `Credentials` sealed interface (`Basic`, `Pkcs12`). `parseDotkon(json, envLookup)` does `${VAR}` env-var expansion (callable lookup so it stays pure for Native), kotlinx-serialization decode with a `type` discriminator, then validates and throws `DotkonValidationException` collecting all field errors.
- **`ServiceDiscovery.kt`** — `ConnectorServices` and friends as xmlutil-serializable types matching `<base>/connector.sds`. `loadConnectorServices(httpClient, baseUrl)` is a suspend GET. `withRewrittenEndpoints(baseUrl)` returns a copy with internal hostnames replaced by the caller's reachable base. `defaultXml` is the shared `XML` instance used by both SDS and SOAP decoding.
- **`ServiceProxy.kt`** — `ServiceProxy.call(operation, request, label)` is the generic SOAP transport. Reified inline overload derives serializers from types: `val resp: GetCardsResponseEnvelope = proxy.call(Operations.GetCards, env)`. Does **not** check HTTP status (SOAP 1.1 transports faults via HTTP 500) but does check the body: a fault throws `SoapFaultException` from here, where the raw XML is still available. `label` is the operation description that lands in the message (e.g. `"ExternalAuthenticate(cardHandle=…)"`), defaulting to `operation.name`. There is no `requireSuccess` any more: it threw from the call site, where only the decoded envelope was in scope, and the fault content is not in there.
- **`SoapFault.kt`** — a namespace-tolerant SOAP 1.1 fault parsed from the raw response body, used for the exception message. The generated envelopes now model faults correctly (see below), but they decode *strictly*: the gematik `Error` schema marks `MessageID`, `Timestamp` and eight `Trace` fields mandatory, so a Konnektor that leaves one out fails the typed decode entirely. `ServiceProxy` therefore falls back to this parser whenever decoding throws — a fault we cannot type is still a fault, and its text is the whole point.

  Faults used to be reported as a bare `… reported a SOAP fault`. The cause was in the generator: SOAP 1.1 sends `faultcode` / `faultstring` / `faultactor` / `detail` **unqualified**, while the generated `Fault` left the namespace off its members, which xmlutil resolves against the enclosing `SOAP-ENV` element; `ignoreUnknownChildren()` then dropped every one of them silently. `<detail>` was also inlined as the payload type rather than the wrapper it is. Both are fixed in `wsdl2openapi` (generator-kotlin, `fault` golden fixture) — **regenerate rather than patching `.api.*` by hand.**

- **`ConnectorClient.kt`** — high-level entry point. `ConnectorClient.connect(httpClient, dotkon)` loads the SDS and honours `rewriteServiceEndpoints`. Resolves `serviceProxy(name, version)` or `latestServiceProxy(name)` (highest semver). Convenience methods `getAllCards()`, `getCardsByType(...)`, `getResourceInformation()` mirror the koap-go surface.
- **`SmcbAuthenticator.kt` / `ConsumerClient.kt`** — `SmcbAuthenticator` is the signing seam (`readCardAutCertificate`, `externalAuthenticate`) that both `ConnectorClient` and `ConsumerClient` implement; The CLI picks one by `--auth-method` (`connector` / `consumer`). `ConsumerClient` talks to a Basis-Consumer: no SDS and no `Context`, endpoints from the `.kon`'s `serviceEndpoints`, same `ServiceProxy` fault handling (see `docs/basis-consumer.md`).
- **`DotkonSecurity.kt`** — JVM-only, **engine-agnostic** translation of [Dotkon] into JSSE building blocks: `Dotkon.toTrustManager()`, `Dotkon.toKeyManagers()`, `Dotkon.toSslContext()`. Pure JDK, no Ktor — usable from any JSSE-backed HTTP client. The per-engine bridge below stays thin.
- **`DotkonAuth.kt`** — engine-agnostic Ktor extension `HttpClientConfig<*>.dotkonAuth(dotkon)`: pre-emptive HTTP basic auth via `defaultRequest`. PKCS#12 credentials are TLS client certs and are no-ops here.
- **`engine/okhttp/DotkonHttpClient.kt`** — thin Ktor/OkHttp bridge. `dotkonOkHttpClient(dotkon) { … }` builds an `HttpClient(OkHttp)`. `OkHttpConfig.dotkonTls(dotkon)` derives an `SSLSocketFactory` via `Dotkon.toSslContext()` and installs a `HostnameVerifier` for `insecureSkipVerify` / `expectedHost`. **SNI caveat:** OkHttp binds SNI to the request URL — `expectedHost` only adjusts hostname *verification*, not the SNI hint sent on the wire. `compileOnly` against OkHttp.

**Why OkHttp and not CIO:** Ktor 3.4.x CIO has its own custom TLS stack with a hard-coded `CertificateType` allowlist of `RSA` / `DSS` — **all ECDSA client certs are silently dropped during the `CertificateRequest` round**, regardless of curve. Konnektor self-signed `.kon` client certs are ECDSA in most modern setups (NIST P-256 typically; brainpool rare), so CIO sends an empty `Certificate` message and mTLS fails at any nginx with `ssl_verify_client on`. OkHttp routes through JSSE, which has no such filter and presents whatever is installed. A previous CIO bridge was deleted for this reason. Adding another JSSE-backed engine (Apache, Java) is the same pattern: a thin file under `engine/<name>/` calling `dotkon.toSslContext()` and feeding the result into that engine's TLS config block.

**The cards (`SMC-B` / `HBA`) are unrelated to this.** Their certs and keys never enter JSSE — the SDK signs JWS challenges via the Konnektor's `ExternalAuthenticate` SOAP call and gets DER-encoded signature bytes back. The mTLS path only sees the `.kon` client cert (when configured via `Pkcs12` credentials).

### HTTP client ownership

The HTTP client is **always provided by the caller** — `ConnectorClient`, `ServiceProxy`, and `loadConnectorServices` all take an `HttpClient`, none of them constructs one and none closes it. `dotkonOkHttpClient` is offered as a convenience for the common .kon-driven case but is not required; any pre-configured Ktor `HttpClient` (any engine that goes through JSSE) works. This mirrors koap-go's split between `NewHTTPClient` (helper) and `NewClient` (user can supply their own `*http.Client`).

### XML namespacing

Every field in the generated DTOs carries an explicit `@XmlSerialName(name, namespace=…)` — **fields without an explicit namespace inherit the parent element's namespace** under xmlutil, which is stricter than Go's `encoding/xml` (which matches by local name only). When porting Go test fixtures verbatim, expect to add namespace prefixes to elements that Go was matching loosely.

## Build memory

The full module has ~800 generated source files. The Kotlin daemon needs more headroom than the default 512m to compile them — `gradle.properties` pins `org.gradle.jvmargs=-Xmx4g` and `kotlin.daemon.jvmargs=-Xmx4g`. If you see `OutOfMemoryError: GC overhead limit exceeded`, that's the cause; bump higher.

## Tests

`./gradlew :connector:test`. JUnit Jupiter via `buildlogic.kotlin-common-conventions`. Tests live in `src/test/kotlin/de/gematik/connector/` and use Ktor `MockEngine` for HTTP fixtures (no real Konnektor needed).

JVM bytecode disallows `.` in method names — so backtick-quoted test names (`fun `parses…dotkon`()`) must spell out "dotkon" rather than `.kon`.
